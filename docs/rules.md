# 리무브 규칙

움직이는 영상에서 간판·창문·표지판처럼 **벽면에 붙은 대상**을 지우는 규칙입니다.
기준 사례는 빠르게 패닝하는 거리 영상에서 벽돌 벽의 입체 간판을 지운 작업입니다.
간판이 보이는 135프레임 전체에서 p95 0.894 px, 최대 2.992 px로 기준을 통과했습니다.

수치(마스크 여백, 반복 횟수, 기준값)는 그 샷의 값입니다. 새 샷에서는 같은 방식으로
다시 정하고, 정한 값을 `work/<shot>/contract.json`에 먼저 적어 둡니다.

## 1. 도구 역할

| 단계 | 도구 | 역할 |
| --- | --- | --- |
| 평면 추적 | **Mocha AE**(After Effects 번들) | 항상 먼저 시도합니다. OpenCV 추적으로 대체하지 않습니다. |
| 독립 검수 | OpenCV ECC·SIFT | 추적에 쓰지 않은 원본 픽셀로 오차를 잽니다. |
| 국소 보정 | OpenCV ECC 호모그래피 | Mocha가 밀린 구간만, 같은 평면의 주변 질감으로 다시 맞춥니다. |
| 클린 플레이트 | 이미지 생성·편집 도구 1회 | 기준 프레임 한 장의 가려진 벽을 만듭니다. |
| 패치 렌더 | Python(OpenCV·NumPy) | 지울 영역만 RGBA 패치 시퀀스로 만듭니다. |
| 합성 | After Effects | 원본과 패치를 분리한 편집 가능한 프로젝트를 만듭니다. |
| 검사 | FFmpeg·ffprobe | 프레임 수·시간·색 태그·전체 디코드를 확인합니다. |

## 2. 샷과 기준을 먼저 고정합니다

1. 원본의 해상도, 유리수 FPS(예: 30000/1001), 프레임 수, 해시를 기록합니다.
   가변 프레임률이면 먼저 CFR 작업본을 만들고 원본은 그대로 둡니다.
2. 사용할 구간과 **대상이 보이는 프레임 목록**을 적습니다. 화면 밖으로 나간 뒤는
   패치를 끝내고 원본을 씁니다. 다시 들어오면 따로 확인합니다.
3. 추적이나 보정을 하기 전에 기준을 정합니다. 기준 사례의 값은 1920×1080 작업
   해상도에서 **p95 1.5 px 이하, 최대 3 px 이하**이고, 분모는 대상이 보이는 프레임 전부입니다.
4. 지울 영역(대상 + 그림자 + 돌출부)과 여백을 정합니다. 이 영역의 원본 픽셀은 추적
   피팅에 쓰지 않고 **검수에만** 씁니다.

## 3. Mocha 평면 추적

- 대상이 붙은 **같은 평면**(같은 벽면)을 추적합니다. 대상, 그림자, 깊이가 다른 창틀·
  돌출부·지나가는 사람은 추적 영역에서 뺍니다.
- Perspective를 켜고 Surface를 대상 위치에 맞춘 뒤 시작·중간·끝과 움직임이 가장 큰
  구간에서 Surface가 벽에 붙어 있는지 봅니다.
- Mocha가 중간에 멈추거나 "center unavailable"을 경고한 뒤의 키는 **쓰지 않습니다**.
  내보낸 키 개수는 유효 구간의 증거가 아닙니다. 유효 범위를 기록합니다.
- 코너 데이터는 AE Corner Pin 순서 **TL, TR, BL, BR**로 내보냅니다. 다각형을 그리는
  순서(TL, TR, BR, BL)와 섞지 않습니다.

## 4. Mocha 결과를 독립 검수합니다

- 추적에 쓰지 않은 원본 대상 픽셀(지울 글자·창틀 등)을 기준 프레임에서 각 프레임으로
  옮겨, ECC 잔차와 SIFT 대응점 오차를 잽니다.
- 합산 p95·최대값과 **최악 프레임**의 p95·최대값을 함께 남깁니다. 측정할 수 없는
  프레임은 0이 아니라 UNKNOWN으로 남기고 분모에 둡니다.
- 기준을 통과하면 6장으로 갑니다. 통과하지 못하면 어디서 밀리는지(프레임 구간·
  위치)를 기록하고 5장의 국소 보정을 합니다. 기준 사례에서 Mocha 단독은 p95 2.636 px,
  최대 7.972 px로 탈락했고, 빠른 패닝 구간에서 최대 약 10 px 밀렸습니다.

## 5. ECC 국소 보정

- Mocha 호모그래피를 초기값으로, 대상 **주변 같은 벽면의 고리 영역**에 정규화 ECC
  호모그래피를 프레임마다 다시 맞춥니다. 기준 프레임을 직접 참조합니다(앞 프레임
  연쇄가 아님).
- 기준 사례 설정: `cv2.findTransformECC`, `MOTION_HOMOGRAPHY`, 반복 120회, eps 1e-6,
  Gaussian 3. 대상과 여백은 피팅 마스크에서 뺐습니다.
- 피팅 마스크를 원본 위에 겹쳐 보고 대상의 **위·아래·좌·우에 지지가 고르게 있는지**
  확인합니다. 한쪽에만 지지가 있으면 반대쪽은 외삽이 되어 틀어집니다.
- 시간 평활화, 화면 밖 코너 고정, 원본 영상 전체 워프로 오차를 숨기지 않습니다.
- 보정한 결과를 4장과 같은 독립 검수로 다시 잽니다. 피팅 점수(ECC 상관값)만으로
  통과시키지 않습니다.
- 보정한 국소 호모그래피는 **그 영역에서만** 유효합니다. 같은 벽의 다른 위치나 다른
  깊이에 재사용하지 않습니다.

## 6. 클린 플레이트

- 기준 프레임 한 장에서 가려진 벽을 만듭니다. 이미지 생성 도구에 지울 대상과 보존할
  벽·창·모서리를 구체적으로 적습니다. 생성은 한 번 하고 결과를 확대해 확인합니다.
- 생성 결과의 실제 해상도·화면비를 확인합니다(기준 사례는 1920×1080 요청에
  1672×941이 나왔습니다). SIFT + RANSAC 호모그래피로 원본에 정합하고, 정합에 쓰지
  않은 대응점으로 정합 오차를 확인합니다.
- 바뀌지 않은 주변 벽에서 색·밝기를 맞춥니다(채널별 보정, 일부 블록은 검수용으로
  남김). 창 안쪽·하늘·짙은 그림자는 색 샘플에서 뺍니다.
- 생성 이미지 전체를 쓰지 않고 **지울 영역만** 패치로 씁니다. 보이지 않던 벽은 추정
  복원이라고 기록합니다.

## 7. 패치 렌더

- 패치를 프레임마다 최종 호모그래피로 옮겨 straight RGBA PNG 시퀀스로 만듭니다.
  RGB와 알파에 같은 변환을 적용하고, 워프는 premultiplied·linear-light에서 합니다.
- **알파 밖 픽셀은 원본과 같아야 합니다**(차이 0). 대상이 화면을 벗어난 뒤 프레임은
  원본만 씁니다.
- 원본의 그레인·블러·노출 변화에 맞춥니다. 위치 오차를 페더·블러를 늘려 숨기지 않습니다.

## 8. After Effects 프로젝트

- 새 프로젝트로 만들고 학생의 열려 있는 작업을 덮어쓰지 않습니다. Python이 JSX를
  만들고, 학생이 **File → Scripts → Run Script File**로 실행합니다.
- 기준 사례 설정: 16 bpc, 작업 색공간 Rec.709 Gamma 2.4, linear blending.
  원본 레이어 위에 패치 시퀀스 레이어를 둡니다.
- 패치를 이미 추적한 풀캔버스 RGBA로 만들었다면 AE에서 Corner Pin을 **다시 적용하지
  않습니다**(이중 변환). Corner Pin 키는 끈 가이드 레이어로만 남길 수 있습니다.
- 저장 후 다시 열어 원본·패치 경로와 대표 프레임 픽셀이 같은지 확인합니다.
  MP4만 있으면 편집 가능한 프로젝트가 아닙니다.

## 9. 최종 검수와 보고

- 최종 MP4 전체를 디코드하고 프레임 수·시간·색 태그(BT.709/TV range)를 확인합니다.
- 독립 검수를 최종 결과로 다시 잽니다: 지운 영역 안 SIFT, 패치 안쪽 경계 띠,
  벽돌 사이 빈 공간. 기준 사례의 최종값은 지운 영역 안 SIFT 27,529개에서
  p95 0.894 px, 최대 2.992 px였고, 최악 프레임의 p95는 2.373 px였습니다.
- 원본과 결과를 같은 시간·크기로 나란히 보며 움직이는 상태로 확인합니다.
  디코드 성공은 화질 검증이 아닙니다.
- 보고에는 수치 통과, 눈으로 본 확인, 남은 한계를 따로 적습니다. 기준을 통과하지
  못한 결과로 브레이크다운이나 공개 영상을 만들지 않습니다.
